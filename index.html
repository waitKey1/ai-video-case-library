什么样的 Case
才算「做完了」

大部分 AI 视频项目失败，不是因为生成质量不够，而是因为完成条件写成了形容词。本文把「成功」拆成可判定的谓词，并给出八个能跑到验收的 Case。

每个 Case 配一个具体的示例产品、输入产出、带阈值的验收清单，以及它的能力边界。

整理于 2026-10-31　·　判据来自五个开源框架的工程实践与自有平台经验　·　不含外部引用数据
判定铁律

一个 Case 能不能跑通，取决于它的完成条件是不是一个谓词 —— 能算出 true / false，而不是一个形容词。

「画面有质感」「调性对」永远判不了，所以这类 Case 做不完。「产品外观相似度 ≥ 0.92」「音画误差 ≤ 3 帧」「字幕 OCR 回读一致率 ≥ 98%」能判，所以这类 Case 一定能收尾。
选 Case 的第一原则：先把验收写成脚本，再决定做不做。

01成功的四个层次

大部分框架失败，是因为把这四层混成了一层。前两层全过了，仍然可能是一条漂亮的垃圾。

层次定义的问题谁能判现状
技术成功文件存在、能播、参数正确机器100% 可自动
感知成功人看着不别扭机器抽检 + 人大部分可自动
品牌成功产品对、宣称对、不违规规则 + 人审半自动
商业成功投放跑得动只有广告平台知道框架测不了

02四道验收门

流水线形态：逐层过滤，前一门不过不进下一门。这四道门构成所有 Case 的公共底座。

门检查内容判据示例不过怎么办
技术门
全自动		 ffprobe 可读 · 时长 · 画幅帧率 · 音轨 · 黑帧 · 时间戳单调 时长误差 ≤ ±0.5s；非静音片必须有有效音轨；无连续黑帧 直接重渲，不进入后续评审
感知门
自动打分		 文字可读 · 运动充分度 · 音画同步 · 主体一致性 字幕有效字高 ≥5% 帧高；音画误差 ≤3 帧；DINO 相似度 ≥0.9 退回对应阶段重做，记录失败原因
品牌门
规则 + 人		 产品外观与实拍一致 · 卖点可追溯 · 无幻觉文字 · 无竞品露出 产品特征点逐项核对；每个卖点能指回 brief 的哪一条 改源文件（brief / 提示词 / 素材），不在成片上打补丁
商业门
框架外		 3 秒完播 · 完播率 · CTR · CVR · ROAS 与客户基线对比，胜出即通过 数据回流，更新品类先验
关键认知

单条成功是概率，变体库的成功率才是判据。

同样的提示词跑十次出两三张能用的，这是常态。所以框架的 KPI 不该是「这条片好不好」，而是「在 N 条变体里，能否稳定产出 M 条超过客户基线的」。
这恰好是 AI 相对传统制作唯一压倒性的优势：变体成本近乎为零。

03八个能跑通的 Case

按「完成条件的可判定程度」组织。每个 Case 都配了示例产品与具体验收阈值，可以直接照着写脚本。

1

商品图转展示视频

难度 低 半确定性

用几张实拍商品图，生成一段有运镜、有卖点字卡的竖版展示片。不涉及人物、不涉及生成文字。

示例产品

「雾屿 Aroma One」桌面香薰机

一个做小家电的新消费品牌，SKU 有六种配色（雾白 / 砂陶 / 墨绿 / 雾蓝 / 奶杏 / 曜黑）。电商详情页已有 6 张棚拍图（正面、45 度、俯视、出水口特写、场景图、尺寸图）。
要做的片子：3 条 15 秒竖版，只做三个主推配色（雾白 / 砂陶 / 墨绿）。每条从特写推近开始，展示雾化瞬间，切到场景图，最后落定品牌字标与「静音 28dB」卖点。

输入
1–5 张商品图 + 卖点文案
→
产出
8–15 秒竖版展示片

完成判据

  • 主体与输入图 相似度 ≥ 0.90（DINO/CLIP，每 30 帧抽检）
  • 画面内 无生成文字（OCR 检出字符数 = 0，字卡单独图层渲染）
  • 时长误差 ≤ ±0.3s，画幅符合订单
  • 每段运动的光流均值 > 阈值（排除静图缓推）
  • 三个配色各生成一条，色差 ΔE ≤ 3
为什么能跑通

全是单主体、无人物交互、无文字。生成模型的不确定性被限制在「外观微变」这一个维度，而这个维度有相似度指标兜底。所有判据都能写成脚本。

边界

产品有透明材质、反光面、或需要展示内部结构时会崩。多件产品同框时主体归属容易错。超过 20 秒后镜头重复感明显。

2

口播短视频批量生成

难度 低–中 近确定性

给一段稿子和一个音色，产出配好音、上好词级字幕的竖版口播片。字幕时间戳从 TTS 直接拿，不做事后对齐。

示例产品

「柔朵」婴儿纸尿裤

母婴品牌，主打「夜用 12 小时不红臀」。目标人群是 0–1 岁宝宝的妈妈，投放渠道以抖音和小红书为主。
要做的片子：4 条 45 秒素人口播，讲「半夜换尿布把全家吵醒」的痛点，落到产品卖点。同一稿子 × 2 个音色 × 2 种开头钩子交叉。

输入
口播稿 + 音色
→
产出
30–60 秒竖版口播片

完成判据

  • 字幕时间戳来自 TTS 词边界，音画峰值互相关误差 ≤ 3 帧
  • 字幕有效字高 ≥ 5% 帧高（1080p 下 ≥56px），按渲染帧实测而非字号设置
  • 无 RMS 低于门限超过 1 秒的静音段
  • 稿件里的产品名与数字，100% 出现在字幕中
  • 同一稿换音色后，时长漂移 ≤ 8%
为什么能跑通

MoneyPrinterTurbo 已经证明这条链：字幕时间戳从 TTS 直接拿，音字同源，根本不需要对齐算法。整条流程没有概率性环节，每个指标都能在渲染产物上量出来。

边界

需要真实人物出镜时，人物一致性会成为新问题。稿子超过 90 秒后节奏容易平。中文多音字需要人工校对表。

3

爆款结构克隆

难度 中 半确定性

给一条跑量的参考片，保留它的节奏结构与钩子类型，换掉内容重新生成。不是换皮，是换骨。

示例产品

「Volo」磁吸充电宝

3C 配件品牌，主投 TikTok 与视频号。团队发现一条竞品的「三秒痛点 + 拆解演示 + 反转」结构连续跑量三个月。
要做的片子：用同一结构做三条，分别对应通勤、出差、露营三个场景。每条前 3 秒必须是「手机没电」的具象画面，第 8 秒出现产品吸附动作，结尾同一句 CTA。

输入
一条参考视频
→
产出
同节奏、换内容的新片

完成判据

  • 镜头时长分布相似度：每个切点的相对位置偏差 ≤ 10%
  • 能量曲线相关性 ≥ 0.8（每镜光流 + 音量的组合曲线）
  • 内容差异度：关键帧感知哈希距离 > 阈值（证明不是换皮）
  • 前 3 秒钩子类型与参考片 一致（按标注规则判定）
  • CTA 出现位置偏差 ≤ 0.5s
为什么能跑通

Hypit 的核心主张正在这里：保留「哪个词触发哪个画面」的关系，换掉词和素材。节奏结构是可量化的，所以可验收；而内容差异度有哈希距离兜底，保证不是简单换皮。

边界

参考片如果依赖真人表演的微表情，结构能抄但味道抄不到。需要人工标注钩子类型，这一步暂时没法全自动。跨品类套结构会显得生硬。

4

一稿多语言

难度 低 完全确定性

一条做好的成片，产出十几到二十个语言版本。纯替换问题，没有创作成分，是本清单里投入产出比最高的一类。

示例产品

「掌勺」多功能料理机（出海）

小厨电品牌，国内版片子已定稿，准备铺东南亚与中东市场。
要做的片子：同一条 40 秒功能片，先做 4 个语言版本：越南语、泰语、印尼语、阿拉伯语。要求画面完全一致，只换配音与烧录字幕；产品名「掌勺」在部分地区改为拼音 CHOPO。

输入
成片 + 目标语言列表
→
产出
10–20 个语言版本

完成判据

  • 字幕行数与原片 一致，无漏译、无空行
  • 配音时长与画面对齐误差 ≤ 0.5s
  • 屏幕文字全部替换，OCR 检出 无原语言残留
  • 每个版本技术门 全过（时长、画幅、音轨）
  • 品牌名按地区对照表替换，零错漏
为什么能跑通

这是纯确定性的替换问题，没有创作成分，所以每一个判据都能精确判定。商业价值也最直接：传统一条素材做二十个市场是二十倍成本，这里是叠加成本。

边界

阿拉伯语、希伯来语需要从右到左排版，字幕位置要重排。有些市场的合规要求不同（如医疗、金融类宣称），需要人审。文化语境差异大时，直译会很别扭，这属于翻译质量问题而非工程问题。

5

数据动效片

难度 低 完全确定性

一份数据加一句结论，产出一段带图表动画的说明片。数字是代码渲染的，不是生成的，不可能错。

示例产品

「账房」财务 SaaS · 年度报告片

面向中小企业的记账 SaaS，要发一份年度行业报告并配一条传播片。
要做的片子：35 秒，用三组数据讲「中小企业平均应收账期从 68 天延长到 91 天」。要求每个数字在屏幕上停留 ≥1.5 秒，最终落定一个可视化对比图。

输入
JSON / 表格 + 一句结论
→
产出
20–40 秒数据动效视频

完成判据

  • 最终帧数值与输入数据 逐位相等（OCR + 数值比对）
  • 图表类型与数据关系匹配（占比用饼/堆叠，趋势用折线）
  • 所有动效有起止状态，无悬空动画
  • 每个数字停留时长 ≥ 1.5s
  • 零生成模型调用（纯代码路径）
为什么能跑通

数字由代码渲染，不可能出错。整个 Case 零生成依赖，是唯一一个理论上 100% 可复现的品类。适合作为框架的第一条打通链路。

边界

数据本身如果有问题，片子会精确地展示错误。观感偏理性，不适合情绪类营销。超过五个图表后注意力会散。

6

产品功能演示

难度 中 确定性

从真实页面截图出发，用虚拟运镜做功能演示。质量上限最高的一类，因为底图是真实像素。

示例产品 · 五个不同形态

「账房」财务 SaaS · 桌面后台

面向中小企业的记账 SaaS，要一条用于官网首屏与销售提案的片子。
要做的片子：50 秒，展示四个核心功能：自动识别发票、一键生成凭证、应收账龄看板、多主体合并报表。每个功能从真实页面截图出发展示，不手搓 UI。

「墨记」笔记 App · 移动端

一款面向写作者的本地笔记应用，主打「离线、纯文本、秒开」。需要一条应用商店预览片。
要做的片子：30 秒竖版，模拟手指操作串起的三个动作：新建、双链跳转、全局搜索。界面全部来自真机截图，手势用层叠位移与遮罩模拟，不做真人手。

「砺刃」桌面修图工具 · 本地客户端

一款面向摄影师的批量修图软件，核心卖点是「一次调色应用到两千张」。需要一条发布片。
要做的片子：40 秒，从单张照片的调色面板推近开始，镜头拉远露出批量队列，最后落定处理速度数字。界面来自真实客户端截图，数字用代码渲染。

「云枢」IoT 设备管理台 · 大屏看板

面向工厂的能耗监控平台，卖点是「异常自动定位到具体产线」。需要一条展会循环播放片。
要做的片子：35 秒横版，从全国地图总览逐级下钻到单台设备告警。整段是一次连续的相机推进，用同一张超长截图做 2.5D 运镜。

「栈桥」开发者 API 平台 · 文档站

面向开发者的数据接口平台，卖点是「三行代码接入」。需要一条嵌在落地页的视频。
要做的片子：25 秒，左侧代码逐行打字出现，右侧返回结果实时弹出，最后并排展示调用量增长曲线。代码和数字都是真实渲染的文本，不经过图片生成。

输入
前端项目 / 网址 / 桌面或移动端截图
→
产出
30–60 秒功能演示片（每个产品 1 条）

完成判据

  • 截图来自真实页面（与源站 DOM 比对，不是手搓）
  • 文字锐度：放大帧的边缘梯度 超过阈值（2 倍栅格化）
  • 每个必须展示的功能都有对应镜头（对 brief 逐项核对）
  • 无敏感数据（脱敏规则表全过）
  • 字幕有效字高 ≥ 56px（1080p）
为什么能跑通

video-shotcraft 的整套方法就是为这个建的，124 张镜头卡里一半是 UI 类。底图是真实截图，所以主体一致性天然 100%，问题只剩运镜和排版。

边界

客户数据敏感，脱敏不彻底会出事。页面状态需要预先准备好（登录态、示例数据）。工时比前几个重得多，不适合走量。

7

长内容切片

难度 低 确定性最高

一小时播客切成十几条短视频。素材已经是现成的，框架只负责选择和切分，不确定性最小。

示例产品

「开店笔记」播客 · 切片矩阵

一个面向小餐饮创业者的播客，每期 60–90 分钟。运营团队需要每期产出短视频，投放到视频号、抖音、小红书、B 站。
要做的片子：从一期「为什么你的店活不过 18 个月」里切出 4 条 30 秒片段，每条有独立钩子和完整语义，配字幕与简单 B-roll。

输入
1 小时播客 / 直播
→
产出
10–20 条 30 秒片段

完成判据

  • 每片有完整语义（起止落在句界，非句中切断）
  • 字幕准确率 ≥ 98%（ASR + 人工抽检 5%）
  • 画面有变化：固定机位静坐 不超过 8 秒，超则加 B-roll 或缩放
  • 每条独立可懂（无指代前文的代词）
  • 4 条覆盖原片 ≥ 30% 的有效内容，不重复
为什么能跑通

确定性最高的一类：素材已经存在，框架只做选择与切分，不生成任何画面。所有判据都能在原始素材和成片上直接量出来。

边界

「哪段值得切」是主观判断，需要给模型明确的选题规则（痛点密度、金句密度、数据密度）。多人对话的说话人归属容易错。

8

广告变体工厂

难度 中 判据在框架外

一条母版派生几十个变体，每个变体带一个明确的投放假设。它是本清单里唯一一个「真正的验收在投放数据里」的 Case。

示例产品

「雾屿」香薰机的投放矩阵

接 Case 1 的同一款产品，进入投放阶段。团队已有的母版是一条 15 秒展示片。
要做的片子：先做 4 条变体验证假设。两个维度交叉：开头钩子（静音痛点 / 颜值展示）× CTA（立即购买 / 领券），其余要素保持完全一致。验证有效后再按同一框架扩到 30 条以上。

输入
一条母版
→
产出
4 条带假设标签的变体
验证后再扩量

完成判据

  • 每个变体过前三道门（技术 / 感知 / 品牌）
  • 变体间感知哈希距离 > 阈值（证明真的不同，不是改标点）
  • 每个变体带一个明确的假设标签（如 H01_痛点开头）
  • 同组变体除受控维度外，其余要素完全一致
  • 投放后 14 天内回收完整数据，无缺失
为什么这个最重要

它是唯一一个真正的验收在框架外的 Case——片子做得再好，投放跑不动就是失败。所以它必须配一个数据回流机制，把「哪个变体赢了」变成下一轮生产的先验。这也是整个 AI 营销的价值中枢。

边界

需要投放平台接口与归因链路，工程量在框架之外。样本量不足时结论不可信（每个变体至少要跑够曝光）。同组要素控制不严会污染结论。

04投产顺序

按「跑通概率 × 商业价值」排序。前三个是纯确定性路径，应该先打通，用来验证框架的骨架。

顺序Case确定性为什么排在这个位置
1多语言完全纯替换，商业价值直接，最适合作为框架第一条端到端链路
2数据动效完全零生成依赖，不可能错，用来验证渲染与验收管线
3长内容切片最高素材现成，只做选择与切分，验证选段与对齐能力
4商品图半最稳的生成类，无人物无文字，验证相似度兜底
5口播近链条成熟，验证 TTS 与字幕同步
6变体工厂半价值最大，但需要投放接口，放在有数据能力之后
7功能演示确定质量上限高但工时重，适合做标杆项目而非走量
8结构克隆半需要参考片拆解能力，组件最复杂，最后做

05真正能突破的五个地方

不是「生成得更好看」——那是模型厂商的事。突破点在于把单条制作变成一门可规模化的生意。

01

从做一条片，到跑一个库

传统制作里，第 2 条到第 50 条的成本几乎线性。AI 的边际成本趋近于零。真正的产品不是更好的单条，而是能稳定产出 50 条可用变体的机器。这个转换传统制作公司做不了，因为他们的人均产能是固定的。

02

结果数据回流成生成先验

这是唯一不可被模型厂商复制的壁垒。别人也能接同样的模型，但他们不知道你的客户里「3 秒内出现产品」比「3 秒内出现人」转化高多少。这个知识只能从投放数据里长出来。

03

素材寿命管理

一条素材投放两周后就疲劳，现在靠人盯。如果能自动检测衰减曲线并提前生成替代变体，这是运营效率的真实提升，不是噱头。

04

多市场并行

不是翻译，是同一条创意骨架在二十个文化语境里同时成立。传统公司成本是 20 倍，AI 是 1.2 倍。而且它天然可判定——语言对不对一眼能看出来。

05

创意与投放一体化

让生成时就带上投放假设，产出物自带 A/B 分组和归因标签。把创意和投放从两个部门变成一个闭环。这是唯一一条能让「做好片子」和「生意变好」直接挂钩的路径，也是这套 Case 库最终要落到的位置。

一句话总结

能跑通的 Case，都是「完成条件可以被机器判定」的 Case。

上面八个里，多语言、数据动效、长内容切片完全确定性；商品图、口播、变体工厂有概率成分但可量化验收；功能演示、结构克隆需要更强的能力。突破点不在于把片子做得更好看，而在于把「一条片」变成「一个能自我迭代的变体库 + 数据闭环」。
